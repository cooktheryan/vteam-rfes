# Data Model: UBI-based vLLM Container

**Feature**: 001-ubi-vllm-container
**Date**: 2025-11-07
**Purpose**: Define key entities, their attributes, relationships, and state transitions

---

## Entity Overview

This container infrastructure project deals with the following key entities:

1. **Container Image**: The built artifact (Containerfile output)
2. **Container Instance**: The running container process
3. **Language Model**: AI model files loaded by vLLM
4. **Configuration**: Runtime parameters and environment variables
5. **Volume Mounts**: Persistent storage attachments
6. **Container Runtime**: Podman/Docker execution environment

---

## 1. Container Image

### Description
The immutable container image artifact built from the Containerfile, containing the UBI base, vLLM runtime, dependencies, and configuration.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `name` | String | Yes | Image name | Format: `ubi-vllm` or `ubi-vllm:<tag>` |
| `tag` | String | Yes | Version identifier | Format: semver (`1.0.0`) or `latest` |
| `registry` | String | Optional | Registry location | URL format, defaults to local |
| `base_image` | String | Yes | UBI CUDA runtime base | Must be `nvcr.io/nvidia/cuda:12.6.1-runtime-ubi9` |
| `size` | Integer | Computed | Image size in bytes | Target: 8-10 GB compressed |
| `layers` | Array | Computed | Image layer hashes | SHA256 checksums |
| `created_at` | Timestamp | Computed | Build timestamp | ISO 8601 format |
| `labels` | Map | Yes | Metadata labels | Include version, maintainer, description |
| `vllm_version` | String | Yes | vLLM package version | Must be `0.6.6` |
| `python_version` | String | Yes | Python runtime version | Must be `3.11` or `3.12` |
| `cuda_version` | String | Yes | CUDA runtime version | Must be `12.6.1` or compatible |

### Relationships
- **Based On**: UBI CUDA runtime base image (parent)
- **Instantiates To**: One or more Container Instances (1:N)
- **Contains**: Configuration defaults (1:1)

### State Transitions
```
[Not Built] --> [Building] --> [Built] --> [Tagged] --> [Pushed to Registry]
                    |              |
                    v              v
                [Build Failed]  [Validated]
```

### Validation Rules
- Image must build without errors
- Image size must be <= 12 GB (warning at 10 GB)
- All required labels must be present
- Base image must be official NVIDIA CUDA UBI variant
- vLLM import must succeed: `python -c "import vllm"`
- CUDA libraries must be present in `/usr/local/cuda/lib64/`

## 2. Container Instance

### Description
A running container process on the RHEL 10 host system, executing the vLLM inference server.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `container_id` | String | Computed | Unique container identifier | Auto-generated by runtime |
| `name` | String | Yes | Human-readable name | Alphanumeric + hyphens |
| `state` | Enum | Computed | Current lifecycle state | One of: created, running, paused, stopped, failed |
| `image_ref` | String | Yes | Source image reference | Must reference valid Container Image |
| `created_at` | Timestamp | Computed | Instance creation time | ISO 8601 format |
| `started_at` | Timestamp | Computed | Last start time | ISO 8601 format |
| `ports` | Array | Yes | Exposed network ports | Default: `8000:8000` for vLLM API |
| `environment` | Map | Yes | Environment variables | See Configuration entity |
| `volumes` | Array | Yes | Volume mounts | See Volume Mounts entity |
| `gpu_allocation` | String | Yes | GPU device assignment | `all` or specific device IDs |
| `ipc_mode` | Enum | Yes | IPC namespace mode | Must be `host` for vLLM tensor parallelism |
| `shm_size` | Integer | Yes | Shared memory size | Minimum 16 GB (16000000000 bytes) |
| `restart_policy` | Enum | Optional | Auto-restart behavior | One of: no, on-failure, always |
| `health_status` | Enum | Computed | Health check result | One of: starting, healthy, unhealthy |

### Relationships
- **Instance Of**: Container Image (N:1)
- **Mounts**: Volume Mounts (1:N)
- **Loads**: Language Model (1:N)
- **Uses**: Container Runtime (N:1)
- **Configured By**: Configuration (1:1)

### State Transitions
```
[Not Exist] --> [Created] --> [Starting] --> [Running] --> [Stopped]
                               |               |              |
                               v               v              v
                          [Failed]      [Restarting]     [Removed]
                                             |
                                             v
                                         [Running]
```

**Detailed Transitions**:
- **Created → Starting**: `podman/docker start` command issued
- **Starting → Running**: Health endpoint `/health` returns 200 OK
- **Starting → Failed**: Startup timeout exceeded (5 minutes) or crash during init
- **Running → Stopped**: `podman/docker stop` command (graceful shutdown)
- **Running → Failed**: Process crash, OOM kill, or health check failure
- **Stopped → Starting**: `podman/docker start` on stopped container
- **Failed → Restarting**: Automatic restart if `restart_policy=on-failure`
- **Stopped → Removed**: `podman/docker rm` command

### Validation Rules
- Container must expose port 8000 (vLLM API default)
- GPU allocation must be valid (device exists on host)
- IPC mode must be `host` for tensor parallelism
- Shared memory must be >= 16 GB
- Health endpoint must respond within 5 minutes of start
- At least one volume mount for model files required
- Environment variable `HF_HOME` must be set

## 3. Language Model

### Description
AI model files (weights, tokenizer, config) that vLLM loads for inference. Models are external to the container image and mounted at runtime.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `model_id` | String | Yes | HuggingFace model identifier | Format: `org/model-name` or file path |
| `model_type` | Enum | Computed | Architecture type | e.g., Llama, Mistral, GPT |
| `size_bytes` | Integer | Computed | Model file size | Typically 5-100+ GB |
| `storage_location` | String | Yes | File system path or HF cache | Must be accessible to container |
| `format` | Enum | Computed | Model file format | One of: safetensors, pytorch, gguf |
| `quantization` | String | Optional | Quantization method | e.g., AWQ, GPTQ, or none |
| `context_length` | Integer | Computed | Maximum sequence length | Extracted from model config |
| `gpu_memory_required` | Integer | Computed | Minimum VRAM needed | Estimated from model size |
| `cached` | Boolean | Computed | Whether model is cached locally | True if in HuggingFace cache |

### Relationships
- **Loaded By**: Container Instance (N:N, multi-model serving)
- **Stored In**: Volume Mounts (N:1)
- **Requires**: GPU allocation (1:1 or more for large models)

### State Transitions
```
[Not Downloaded] --> [Downloading] --> [Downloaded] --> [Cached]
                          |                             |
                          v                             v
                    [Download Failed]              [Loading] --> [Loaded]
                                                        |            |
                                                        v            v
                                                  [Load Failed]  [Serving]
```

### Validation Rules
- Model files must exist at specified path
- Model format must be compatible with vLLM 0.6.6
- Model size must fit within available GPU memory
- HuggingFace models require valid cache directory
- Model config must contain required fields (architecture, vocab_size)
- For multi-model serving, models must fit in allocated GPU memory simultaneously

## 4. Configuration

### Description
Runtime configuration parameters passed to the container instance via environment variables and command-line arguments.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `model_name` | String | Yes | Model to load | Must match Language Model `model_id` |
| `host` | String | Optional | Bind address | Default: `0.0.0.0` |
| `port` | Integer | Optional | API server port | Default: `8000`, range: 1024-65535 |
| `gpu_memory_utilization` | Float | Optional | Fraction of GPU memory to use | Range: 0.0-1.0, default: 0.9 |
| `max_model_len` | Integer | Optional | Maximum sequence length | Must be <= model's context_length |
| `dtype` | Enum | Optional | Data type for weights | One of: auto, float16, bfloat16, float32 |
| `tensor_parallel_size` | Integer | Optional | Number of GPUs for parallelism | Must be <= available GPUs |
| `max_num_seqs` | Integer | Optional | Max concurrent sequences | Affects memory usage |
| `api_key` | String | Optional | API authentication token | Recommended for production |
| `hf_token` | String | Optional | HuggingFace access token | Required for gated models |
| `log_level` | Enum | Optional | Logging verbosity | One of: debug, info, warning, error |

### Environment Variable Mappings

| Config Attribute | Environment Variable | Default |
|------------------|---------------------|---------|
| `hf_token` | `HUGGING_FACE_HUB_TOKEN` | None |
| Cache directory | `HF_HOME` | `/root/.cache/huggingface` |
| vLLM cache | `VLLM_CACHE_ROOT` | Auto-detected |
| GPU devices | `CUDA_VISIBLE_DEVICES` | `all` |
| Logging config | `VLLM_LOGGING_CONFIG_PATH` | None (use defaults) |

### Relationships
- **Configures**: Container Instance (1:1)
- **References**: Language Model (1:1 or 1:N for multi-model)

### Validation Rules
- `model_name` must reference accessible model
- `port` must not conflict with host ports
- `gpu_memory_utilization` must leave room for system overhead
- `tensor_parallel_size` must be power of 2 (1, 2, 4, 8)
- `dtype` must be supported by model and GPU
- `api_key` should be set for production deployments
- `hf_token` required for private/gated models

## 5. Volume Mounts

### Description
Persistent storage bindings that attach host file system paths to container paths, primarily for model files, cache, and logs.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `host_path` | String | Yes | Source path on host | Must exist and be accessible |
| `container_path` | String | Yes | Destination path in container | Absolute path |
| `mount_type` | Enum | Yes | Mount type | One of: bind, volume, tmpfs |
| `read_only` | Boolean | Optional | Read-only flag | Default: false |
| `selinux_label` | Enum | Yes | SELinux relabeling mode | One of: z (shared), Z (private), none |
| `purpose` | Enum | Yes | Mount purpose | One of: models, cache, logs, config |
| `size_limit` | Integer | Optional | Max size for tmpfs | Only for tmpfs mounts |

### Standard Mount Configurations

| Purpose | Host Path Example | Container Path | SELinux | Read-Only |
|---------|-------------------|----------------|---------|-----------|
| HuggingFace Cache | `~/.cache/huggingface` | `/root/.cache/huggingface` | `:Z` | No |
| Model Files | `/opt/models` | `/models` | `:ro,Z` | Yes |
| Application Logs | `/var/log/vllm` | `/app/logs` | `:Z` | No |
| Custom Config | `/etc/vllm/config.json` | `/config/vllm.json` | `:ro,Z` | Yes |
| Shared Memory | `/dev/shm` | `/dev/shm` | N/A | No |

### Relationships
- **Mounted By**: Container Instance (N:1)
- **Stores**: Language Model files (1:N)
- **Contains**: Logs, cache data (1:N)

### Validation Rules
- Host path must exist before container start (or be created automatically for volumes)
- Container path must be absolute
- SELinux label required on RHEL/Podman (`:z` or `:Z`)
- Shared memory mount must have minimum 16 GB via `--shm-size`
- Cache directory must be writable (not read-only)
- Model directory can be read-only if models pre-downloaded

## 6. Container Runtime

### Description
The container execution engine (Podman or Docker) on the RHEL 10 host system.

### Attributes

| Attribute | Type | Required | Description | Validation Rules |
|-----------|------|----------|-------------|------------------|
| `runtime_type` | Enum | Yes | Engine type | One of: podman, docker |
| `version` | String | Yes | Runtime version | Podman >= 4.0, Docker >= 20.0 |
| `nvidia_runtime` | Boolean | Yes | GPU support enabled | Must be true for vLLM |
| `rootless_mode` | Boolean | Computed | Running without root | Optional for enhanced security |
| `selinux_enabled` | Boolean | Yes | SELinux enforcement | Must be true on RHEL 10 |
| `host_os` | String | Yes | Operating system | Must be RHEL 10 |
| `gpu_driver_version` | String | Yes | NVIDIA driver version | Must be >= 535 |

### Relationships
- **Executes**: Container Instances (1:N)
- **Manages**: Container Images (1:N)

### Validation Rules
- NVIDIA Container Toolkit must be installed (`nvidia-container-toolkit` package)
- GPU devices must be visible to runtime
- Runtime must support `--device nvidia.com/gpu=all` (Podman) or `--gpus all` (Docker)
- SELinux must be enabled and enforcing on RHEL 10
- User must have permissions to run containers (in `docker` group or rootless Podman)

## Data Flow

### Container Build Flow
```
Containerfile → Container Image Build → Layer Creation → Image Tagged → Image Stored
     ↓                    ↓                    ↓              ↓             ↓
   Layers          Base: CUDA UBI9      vLLM Install    Metadata      Local/Remote
                   + Python 3.11        Dependencies    Labels        Registry
                   + System Packages    Configuration   Manifest
```

### Container Runtime Flow
```
User Command → Container Instance Created → Volume Mounts Attached → GPU Allocated
     ↓                    ↓                         ↓                     ↓
  podman run       Image Pulled (if needed)  SELinux Labels Applied   CUDA Initialized
                                                     ↓
                                            Model Files Accessible
                                                     ↓
                                              vLLM Server Started
                                                     ↓
                                              Health Check Passed
                                                     ↓
                                              [Container Running]
```

### Inference Request Flow
```
HTTP Request → Container Port 8000 → vLLM API Server → Model Loaded in GPU
     ↓                  ↓                   ↓                   ↓
  /v1/completions   Container Instance   Request Queue    Inference Engine
                    (Running State)      Processing       (GPU Computation)
                                             ↓                   ↓
                                        Response Generated  ← Results
                                             ↓
                                        HTTP Response → User
```

## Constraints and Business Rules

### Global Constraints
1. **Single Container = Single vLLM Instance**: One container instance runs one vLLM server process
2. **GPU Exclusivity**: Each container should have exclusive access to assigned GPUs (no sharing without multi-instance GPU)
3. **Model Immutability**: Loaded models cannot be changed without container restart
4. **Network Binding**: vLLM API must be accessible on container port 8000

### Validation Rules Summary
1. Container Image must pass build validation before deployment
2. Container Instance must have GPU access (enforced by runtime)
3. Language Model must fit in allocated GPU memory
4. Volume Mounts must have correct SELinux labels on RHEL
5. Configuration must specify at least one model to load
6. Health endpoint must respond within 5 minutes of startup

### Performance Constraints
- Container startup time: <= 5 minutes (NFR-003 from spec)
- Memory overhead: Container runtime adds ~500 MB to vLLM's base memory usage
- Storage overhead: Container image size 8-10 GB + model files (variable)

## Notes

This data model focuses on infrastructure entities rather than traditional application data models. The entities represent the physical and logical components of a containerized vLLM deployment on RHEL 10.

For API request/response schemas (OpenAPI), see the `contracts/` directory.
