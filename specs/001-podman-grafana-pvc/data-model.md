# Data Model: Podman Grafana with Persistent Storage

**Feature**: 001-podman-grafana-pvc
**Date**: 2025-11-06
**Type**: Documentation Deliverable

## Overview

This feature is a documentation-only deliverable focused on deployment procedures. However, understanding the logical entities and their relationships is important for comprehensive documentation.

---

## Entity: Deployment Environment

Represents the host system where Grafana will be deployed.

### Attributes
- **Operating System**: RHEL/CentOS or compatible Linux distribution
- **Podman Version**: Installed and operational (rootless or rootful)
- **SELinux Status**: Enforcing (standard for RHEL/CentOS)
- **Available Disk Space**: Minimum 2GB for persistent volume
- **Network Port**: Default 3000 (configurable)
- **User Context**: Rootless Podman user with lingering enabled

### Validation Rules
- Podman must be installed and accessible via `podman --version`
- SELinux must be enforcing or permissive (documented for enforcing)
- Target port must not be in use by another service
- User must have permissions to create directories for persistent storage
- User must have permissions to enable systemd user services

### State Transitions
1. **Uninitialized** → Prerequisites validated → **Ready for Deployment**
2. **Ready for Deployment** → Container deployed → **Running**
3. **Running** → Container stopped → **Stopped**
4. **Stopped** → Container started → **Running**
5. **Running** → Container removed → **Ready for Deployment** (with data preserved)

---

## Entity: Persistent Volume

Represents the host directory providing durable storage for Grafana data.

### Attributes
- **Host Path**: Absolute path on host filesystem (e.g., `~/grafana-data`)
- **Container Mount Point**: `/var/lib/grafana` (fixed for Grafana)
- **SELinux Context**: `container_file_t` with private unshared label (`:Z` flag)
- **Ownership**: Managed by Podman UID mapping (container UID 472)
- **Size**: Dynamic, minimum 2GB recommended
- **Persistence Scope**: Survives container stop, remove, and system reboot

### Validation Rules
- Host directory must exist before container deployment
- Parent directory must be writable by deployment user
- SELinux context must be set via `:Z` flag in volume mount
- Directory must be accessible after system reboot

### Data Contents
The persistent volume contains all Grafana runtime data:
- SQLite database (`grafana.db`)
- Dashboard definitions (JSON files)
- User accounts and permissions
- Data source configurations
- Plugin data and cache
- Session data
- Alert rules and notification channels

### Relationships
- **Belongs to**: One Deployment Environment
- **Mounted by**: One Grafana Container Instance
- **Contains**: Multiple Grafana Data Objects (dashboards, datasources, users)

---

## Entity: Grafana Container Instance

Represents the running or stopped Grafana container.

### Attributes
- **Container Name**: User-defined (e.g., `grafana`)
- **Image**: `grafana/grafana` (official image from Docker Hub)
- **Image Tag**: `latest` or specific version (e.g., `10.2.0`)
- **Container ID**: Generated by Podman
- **Status**: Created, Running, Stopped, Removed
- **Port Mapping**: Host port → Container port 3000
- **Volume Mount**: Host directory → `/var/lib/grafana:Z`
- **Restart Policy**: Managed by systemd (on-failure)

### Validation Rules
- Container name must be unique on the host
- Image must be pullable from registry
- Host port must be available
- Volume mount must specify SELinux flag (`:Z`)
- Container must run as UID 472 (Grafana default)

### State Transitions
1. **Not Exists** → Image pulled → **Image Available**
2. **Image Available** → Container created → **Created**
3. **Created** → Container started → **Running**
4. **Running** → Container stopped → **Stopped**
5. **Stopped** → Container restarted → **Running**
6. **Stopped** → Container removed → **Not Exists** (data in persistent volume remains)
7. **Not Exists** → Redeployed with same volume → **Running** (with previous data)

### Relationships
- **Runs on**: One Deployment Environment
- **Mounts**: One Persistent Volume
- **Managed by**: One Systemd Service (optional but recommended)
- **Exposes**: One Web Interface (Grafana UI)

---

## Entity: Systemd Service

Represents the systemd unit managing container lifecycle.

### Attributes
- **Service Name**: `container-grafana.service`
- **Service Type**: User service (`~/.config/systemd/user/`)
- **Enable Status**: Enabled (auto-start on boot) or Disabled
- **Active Status**: Active (running), Inactive (stopped), Failed
- **Restart Policy**: `on-failure` (default)
- **User Lingering**: Required (enabled/disabled)

### Validation Rules
- Service file must be placed in `~/.config/systemd/user/`
- User lingering must be enabled for boot persistence
- Service must reference correct container name
- `--new` flag ensures clean container recreation

### State Transitions
1. **Not Exists** → Generated from container → **Generated**
2. **Generated** → Installed to systemd → **Installed**
3. **Installed** → Enabled → **Enabled**
4. **Enabled** → Started → **Active**
5. **Active** → Stopped → **Inactive**
6. **Inactive** → Restarted → **Active**
7. **Active** → Container crashes → **Failed** → Auto-restart → **Active**

### Relationships
- **Manages**: One Grafana Container Instance
- **Owned by**: One Deployment Environment (user context)
- **Depends on**: Podman service availability

---

## Entity: Grafana Web Interface

Represents the user-facing Grafana application.

### Attributes
- **Access URL**: `http://localhost:3000` (or host IP)
- **Default Credentials**: admin/admin (first login prompts password change)
- **Authentication**: Local user database (persisted in volume)
- **Configuration**: Stored in `/var/lib/grafana/grafana.db` (SQLite)

### Validation Rules
- Must be accessible within 1 minute of container start
- Must prompt for password change on first login
- Must retain all dashboards after container restart
- Must retain all users after container restart

### Relationships
- **Provided by**: One Grafana Container Instance
- **Stores data in**: One Persistent Volume
- **Accessed by**: Administrators and users via HTTP

## Data Flow: Deployment to Persistence Verification

```
1. Administrator creates host directory
   └─> Persistent Volume (Created)

2. Administrator runs podman command with volume mount
   ├─> Podman pulls grafana/grafana image
   ├─> Container Instance (Created)
   ├─> Persistent Volume mounted to /var/lib/grafana
   └─> Container Instance (Running)

3. Administrator accesses Grafana web interface
   ├─> Creates dashboard
   ├─> Dashboard JSON written to Persistent Volume
   └─> Dashboard visible in Grafana UI

4. Administrator stops and removes container
   ├─> Container Instance (Stopped)
   ├─> Container Instance (Removed)
   └─> Persistent Volume (Unchanged - data preserved)

5. Administrator redeploys container with same volume
   ├─> New Container Instance (Created)
   ├─> Same Persistent Volume mounted
   ├─> Grafana reads data from volume
   └─> Dashboard from step 3 visible (persistence verified)

6. Administrator generates systemd service
   ├─> Systemd Service (Generated)
   ├─> Systemd Service (Installed)
   └─> Systemd Service (Enabled)

7. System reboots
   ├─> Systemd starts user services (lingering enabled)
   ├─> Systemd Service starts Container Instance
   └─> Container Instance (Running with persisted data)
```

## Deployment Interface Contract

While this is a documentation deliverable, the deployment interface represents a contract between the documentation and the user.

### Input Requirements
- **Prerequisites Validated**: Podman installed, SELinux status known, disk space available
- **User Decisions**: Host directory path, container name, host port
- **Optional**: Grafana version (image tag)

### Output Guarantees
- **Grafana Running**: Accessible via specified port within 1 minute
- **Data Persisted**: All configuration survives container removal
- **Auto-Start Configured**: Container starts on system boot (if systemd service created)
- **Logging Available**: Container logs accessible via `podman logs` or `journalctl`

### Error Conditions
- **SELinux Denial**: Missing `:Z` flag on volume mount
- **Port Conflict**: Specified port already in use
- **Permission Denied**: User lacks permissions for directory or systemd service
- **Image Pull Failure**: Network issue or invalid image reference
- **Service Start Failure**: Lingering not enabled, systemd service misconfigured

## Summary

This data model describes the logical entities involved in deploying Grafana with Podman and persistent storage. While this is a documentation deliverable (no source code), understanding these entities, their attributes, validation rules, and relationships ensures comprehensive and accurate documentation.

The key insight is that **persistence** is achieved through the relationship between the Persistent Volume and the Grafana Container Instance, mediated by Podman's volume mounting with proper SELinux context (`:Z` flag). The Systemd Service ensures **reliability** by managing container lifecycle and auto-start on boot.
